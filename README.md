# Посещаемость — Telegram-бот + Mini App для старост

Один бот. Староста создаёт группу в Mini App и делится ссылкой-приглашением; студенты вступают по ней, вводят ФИО и
отмечают себя «был / не был» на парах. Староста отмечает себя так же, а ещё видит сводку, правит чужие отметки,
отменяет пары и редактирует расписание. Весь функционал — внутри Mini App; бот только открывает его (`/start`, кнопка меню).

Бот получает обновления по вебхуку: при старте сервер сам вызывает `setWebhook` на `WEBAPP_URL/telegram/webhook`
с секретным заголовком (выводится из токена), поэтому реплик может быть сколько угодно. Для локального запуска
без публичного HTTPS есть `BOT_MODE=polling`.

## Правила
- Расписание задаётся заранее: день недели, время, предмет, аудитория, преподаватель; пары повторяются каждую неделю.
- Студент отмечается с 15 минут до начала пары и до 30 минут после (в часовом поясе группы) и может менять отметку, пока окно открыто.
  Кто не отметился, автоматически получает «не был» (помечено «авто»; считается на лету, ручная отметка главнее).
  Староста может править любые отметки уже начавшихся пар.
- В начале пары бот присылает напоминание всем, кто ещё не отметился (одно на пару, без дублей даже при
  нескольких репликах; если сервер был недоступен, напоминания досылаются, пока окно отметки открыто).
  Бот может писать только тем, кто разрешил: Mini App один раз запрашивает разрешение (`requestWriteAccess`).
- У пары может быть период действия (например, 01.09–24.10): вне него пара не показывается и не идёт в статистику.
- Студент видит только свою статистику и счётчики по паре; поимённый список — только у старосты.
- Один пользователь — одна группа. Удаление пары удаляет и историю отметок по ней.

## Импорт расписания
Староста: «Расписание» → «Импорт из таблицы факультета» → ссылка на Google Таблицу / файл на Google Диске
или загрузка `.xlsx`. Парсер рассчитан на сетку вида «день недели | время | N группа (подгруппы А/Б)»,
как в расписаниях ФПМИ БГУ:
- лекции, объединённые на поток, и практики по подгруппам (разные преподаватели и аудитории — через «/»);
- сокращения практик расшифровываются по полным названиям лекций из того же файла (МА → Математический анализ);
- даты: «(01.09 - 24.10)», «с 26.10», смена предмета «МА с 28.09 - АГ», несколько курсов подряд в одной ячейке,
  разовые занятия «ОиМП 24.10», нестандартное время «(9.45-11.05)»; пометки чётных/нечётных недель
  не поддерживаются — такие пары импортируются как еженедельные и помечаются в предпросмотре;
- всё, что не удалось однозначно разобрать, показывается в предпросмотре с пометкой — проверьте перед импортом.

По ссылке файл должен быть доступен «всем, у кого есть ссылка». Сервер берёт из ссылки только ID файла
и сам строит URL Google — произвольные адреса не запрашиваются.

## Стек
Go (Gin, pgx) · PostgreSQL 16 · React + TypeScript (Vite) · Caddy (HTTPS) · Docker Compose.

## Деплой
Один образ (`Dockerfile` в корне): Go-сервер отдаёт и API, и собранный Mini App. Миграции применяются при старте.

### Railway
1. New Project → Deploy from GitHub repo → этот репозиторий (ветка `master`). Корневой `Dockerfile`
   и `railway.toml` (healthcheck `/healthz`) подхватятся сами.
2. В проект: + New → Database → PostgreSQL.
3. Variables сервиса приложения:
   - `DATABASE_URL` = `${{Postgres.DATABASE_URL}}`
   - `BOT_TOKEN` — токен из @BotFather
   - `BOT_USERNAME` — username бота без @
   - `WEBAPP_URL` = `https://perazou.wydentis.xyz`
   - `MINIAPP_SHORT_NAME` — только если Mini App именованное (см. ниже)
   - `ADMIN_USERNAMES` / `ADMIN_IDS` — кому доступна вкладка «Админ» со всеми пользователями и группами
     (через запятую; username без @, сверяется по подписанным Telegram данным)
4. Settings → Networking → Custom Domain → `perazou.wydentis.xyz`; у регистратора домена добавьте
   записи, которые покажет Railway (CNAME на `*.up.railway.app`, при необходимости TXT для проверки).
5. После деплоя в Deploy Logs должна появиться строка `bot: webhook registered at …`. Пока домен или
   сертификат не готовы, сервер повторяет регистрацию с нарастающей паузой — это нормально.

### Свой сервер (docker compose)
`cp .env.example .env`, заполните, `docker compose up -d --build`. Caddy получает HTTPS-сертификат
для `DOMAIN` (DNS должен указывать на сервер, порты 80/443 свободны).

### @BotFather
`/newapp` или Bot Settings → Configure Mini App → URL `https://<домен>`. Если это *Main Mini App*,
ссылка приглашения — `t.me/<bot>?startapp=CODE`; если именованное приложение — укажите `MINIAPP_SHORT_NAME`.

## Разработка
```bash
docker run -d --name att-pg -e POSTGRES_PASSWORD=pg -e POSTGRES_DB=att -p 5432:5432 postgres:16-alpine
# API; DEV_AUTH принимает заголовок X-Dev-User: "<id>:<имя>" (percent-encoded) вместо подписи Telegram (только локально!)
# с настоящим ботом добавьте BOT_TOKEN=… BOT_MODE=polling WEBAPP_URL=… (вебхуку нужен публичный HTTPS)
cd backend && DATABASE_URL='postgres://postgres:pg@localhost:5432/att?sslmode=disable' DEV_AUTH=true go run .
# Фронт: http://localhost:5173/?dev=1:Иван — id пользователя и имя
cd frontend && npm i && npm run dev
```
Тесты: `cd backend && go test ./...`; прогон парсера на реальном файле:
`SCHEDULE_XLSX=file.xlsx SCHEDULE_GROUP="4 группа" go test -run TestRealSchedule -v`

## Безопасность
Каждый запрос несёт `Authorization: tma <initData>`; бэкенд проверяет HMAC-подпись по токену бота и свежесть
`auth_date` (24 ч). Роль (староста/студент) определяется только по БД.
